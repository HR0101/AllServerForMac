# AllServerForMac（Mac 動画サーバー）

自宅の Mac を「個人用メディアサーバー」にする SwiftUI 製 macOS アプリです。Mac 内の動画・写真を同一 Wi‑Fi 上の iPhone アプリ（[VideoPlayer](../VideoPlayer)）やブラウザから閲覧・再生できます。

> ペアになるクライアント: iOS アプリ **VideoPlayer**（Bonjour で自動検出）

---

## 主な機能

- **HTTP 配信サーバー**（[Swifter](https://github.com/httpswift/swifter) ベース）でアルバム / 動画 / 写真 / サムネイルを配信
- **Bonjour 公開**（`_myvideoserver._tcp.`）で、クライアントが LAN 内のサーバーを自動検出
- **ブラウザ UI** 内蔵（`/` にアクセスするとそのまま閲覧可能）。**ホーム / ショート / 続きを見る / アルバム** の 4 タブ構成で、Mac は左サイドレール、スマホは下タブバーに自動で切り替わる（[詳細](#ブラウザ-ui4-タブ)）
- **アルバム管理**（作成・削除・動画の移動、`ALL VIDEOS` / `ALL PHOTOS` 仮想アルバム）
- **サムネイル自動生成**（動画はフレーム抽出、AVFoundation 使用）
- **PIN 認証**：Web/クライアントからのアクセスに 6 桁 PIN を要求（ヘッダ `X-Auth-PIN` / Cookie `pin` / クエリ `pin` の 3 経路に対応）
- **アクセスログ**（直近 200 件、IP・メソッド・パス・認可結果）
- **1080p オンデマンド変換**：クライアントが「1080p」を選んだ時だけ低画質プロキシをその場で生成し、視聴終了で自動削除（常に 1 本分のみ保持しストレージを圧迫しない）
- **自動停止タイマー**：指定時間で無操作なら完全終了して省電力
- **スケジュール起動/停止**：毎日決まった時刻に起動・終了（`launchd` の LaunchAgent + スリープ起床は `pmset`）
- **ストレージ管理画面**（容量集計、孤立プロキシの掃除、Finder で開く）
- **差分切り替え再生**：同じ尺・同じ動きで絵だけが違う「差分動画」を自動で束にし、選んだ数本を完全同期で走らせたまま、一定間隔やキー操作で見せる 1 本だけを差し替える（[詳細](#差分切り替え再生)）

---

## 動作環境

- macOS 15.5 以降
- Xcode（Swift / SwiftUI）
- 依存: Swifter（Swift Package Manager で導入済み）
- App Sandbox: **無効**（`launchctl` / `pmset` / LaunchAgent 書き込みのため）。エンタイトルメントは `com.apple.developer.networking.multicast` のみ。

## ビルドと起動

1. `AllServerForMac.xcodeproj` を Xcode で開く
2. ターゲット `AllServerForMac` を実行（▶）
3. アプリ画面で **ポート番号**（既定 8080）を確認し「開始」を押す
4. 同じ Wi‑Fi 上の iPhone で VideoPlayer を開くと、サーバーが自動的に一覧に出ます

> スケジュール起動を使う場合は、ビルドしたアプリを `/Applications` など**固定の場所**へ配置してから設定画面で「適用」してください（plist にアプリのパスを書き込むため）。

## データの保存場所

| 種類 | パス |
|---|---|
| ライブラリ DB | `~/Movies/MacVideoServerData/library.json` |
| 取り込み動画 | `~/Movies/MacVideoServerData/Videos/` |
| サムネイル | `~/Movies/MacVideoServerData/Thumbnails/` |
| プロキシ（一時） | `~/Movies/MacVideoServerData/Proxies/` |
| 差分検出のフレーム指紋 | `~/Movies/MacVideoServerData/VariantSignatures.json`（作り直せるので消しても可） |
| ダウンロード取込先 | `~/Downloads/VideoServerForMac_Media/` |

起動時に上記の保存先を準備できない場合は，空のライブラリで処理を続けず，ライブラリ読み込みとHTTPサーバーを停止します．画面に表示される対象パスとエラー理由を確認し，フォルダの読み書き権限，ディスクの空き容量，保存先ボリュームの接続状態を解決してからアプリを再起動してください．

## HTTP API（抜粋）

すべて PIN 認証が有効なときは認可が必要です（`/` とサムネイルの一部を除く）。

| メソッド | パス | 説明 |
|---|---|---|
| GET | `/` | ブラウザ用 Web UI |
| GET | `/albums` | アルバム一覧（JSON） |
| GET | `/album/:id/videos` | アルバム内のメディア一覧（JSON） |
| GET | `/video/:id?q=original\|1080p` | 動画ストリーム（プロキシがあれば配信、無ければオリジナル） |
| GET | `/video/:id/prepare?q=1080p` | 1080p プロキシをオンデマンド生成し、進捗を返す（`{state, progress}`） |
| DELETE | `/video/:id/proxy` | オンデマンドプロキシを全削除（視聴終了時のクリーンアップ） |
| GET | `/thumbnail/:id` | サムネイル（JPEG） |
| GET | `/server/status` | 稼働時間（JSON） |
| POST | `/server/shutdown` | サーバーを完全終了 |
| POST | `/albums/create` | アルバム作成 |
| DELETE | `/albums/:id` | アルバム削除 |
| POST | `/move` | 動画をアルバム間で移動 |
| POST | `/deleteVideos` | 動画削除 |

## ブラウザ UI（4 タブ）

`/` を開くと、iOS / Android クライアントと同じ構成の画面が出ます。タブは **ホーム / ショート / 続きを見る / アルバム** の 4 つ。実体は
`Features/Server/Services/WebClientHTML.swift` の生文字列 1 本（HTML + CSS + JS）で、
外部アセットはありません。**Web プレイヤーを直すときはこの文字列を編集します。**

| タブ | 中身 | 元になっているクライアント側の画面 |
|---|---|---|
| ホーム | `ALL VIDEOS` をシャッフルした YouTube 風フィード（16:9 の大サムネ＋タイトル＋アルバム名・投稿からの経過時間）。数本おきに「おすすめショート」の横スクロール棚を挟む | `RemoteVideoListView`（`albumID == "HOME"`） |
| ショート | 全動画をシャッフルし、1 本ごとに**ランダムな開始位置から 60 秒**だけ再生する縦型プレイヤー。スワイプ / ホイール / ↑↓ で送り、シークバーは**ドラッグ可**（← → で 5 秒送り） | `RemoteShortsPlayerView`（`albumID == "SHORTS"`） |
| 続きを見る | 途中でやめた動画だけを、最後に見た順に並べる。残り時間と視聴率つき | （Web 独自） |
| アルバム | 従来のアルバム一覧 → 詳細グリッド（検索・並べ替え・アルバム単位のショート再生） | `AlbumListView` |

「ショート＝60 秒以下の動画」の判定は iOS 版の `isShortVideo` と同じです。

棚を挟む間隔は**列数に合わせて変えます**。スマホ（1 列）は iOS 版と同じ「1 本目の次、以降 4〜10 本おき」。
Mac は 1 行に何本も並ぶので同じ規則だと棚だらけになるため、**行数**で数えて「横動画を 2 行見せてから、以降 2〜4 行おき」にしています
（5 列なら 10 本見せてから 10〜20 本おき）。列数は `feedColumns()` が実際のグリッドから読み取ります。

棚の中身は、読み込みのたびに切り直す 1 つの「山札」（`state.shortsDeck`）から**棚ごとに違う区間を順に切り出し**ます。
棚ごとに無作為抽出すると偶然かぶるので、配り方式にして重複を避けています。

### スマホと Mac の出し分け

**1 つの HTML をメディアクエリ（境界 900px）で切り替えます**。ユーザーエージェント判定はしません。

| | スマホ（〜900px） | Mac / 広い画面（901px〜） |
|---|---|---|
| ナビ | 画面下のタブバー（4 タブ・`env(safe-area-inset-bottom)` 対応） | 左サイドレール 240px（901〜1099px はアイコン主体の 76px ミニレール） |
| ホーム | 1 列・端から端までのサムネ | `auto-fill` の複数列（1 列あたり最小 310px） |
| 検索 | 虫めがねを押すと展開 | 上部バーに常時表示 |
| 再生画面 | 上部に 16:9 固定＋下に「次の動画」が縦スクロール | 左に大きなプレイヤー、右に 400px の再生リスト |
| 再生画面のスクロール | 動画は上に固定、下のリストだけが動く | 左右が**独立してスクロール**する。リストを送っても動画は動かない（見出しは上に貼り付く） |
| ショート | 全画面（上部バーは隠れ、下タブバーは残る）・操作ボタンは右下に重ねる | 中央に 9:16 の枠、操作ボタンは枠の右外 |
| ショートの「表示サイズ」 | 枠は画面いっぱいのまま、映像を拡大して余白を埋める（＝切り取られる） | **枠そのものを動画の形に近づけて広げる**（切り取らない）。横長動画ほど大きく表示される |
| サムネのプレビュー | なし（タップで再生） | カーソルを 0.7 秒乗せるとミュートで再生 |

### 再生画面の「10 等分サムネ」

動画の再生画面では、プレイヤーの直下に**動画を 10 等分した地点のサムネ**を並べます。押すとその時間へ飛び、
再生中の区間は枠が光ります。スマホ・Mac 共通で、横スクロールする帯です。

- サーバーの `GET /thumbnail/:id?original=true&time=<秒>` をそのまま使います。生成物は `<UUID>_t<秒>.jpg` として
  キャッシュされるので、2 回目以降は即座に返ります。
- 秒はサムネ名で整数に切り捨てられるため、刻みが 1 秒未満だと同じ絵が並びます。これを避けるため
  **20 秒以下の動画では帯を出しません**（`CHAPTER_MIN_DURATION`）。
- 先頭は真っ黒なことが多いので、0 秒ではなく再生時間の 1% 地点を使います（飛び先も同じ位置）。
- 10 枚を一斉に要求すると、指定フレーム抽出（`AVAssetImageGenerator`、許容誤差ゼロ）とブラウザの同時接続数を
  動画本体のストリームと奪い合います。そのため**常に 2 枚ずつ順番に**読み込みます。
- 動画を切り替えたら `state.chapterToken` を進めて、前の動画のサムネ読み込みを打ち切ります。

### 削除方法は3種類

Macアプリ，Webクライアント，iOSクライアントでは削除方法を共通化しています．リンクフォルダの元ファイルへ触れるのは，明示的に「Macのゴミ箱へ移動」を選んだ場合だけです．

| ボタン | 叩く API | 実際に起きること |
|---|---|---|
| アプリ内のゴミ箱へ | `POST /deleteVideos`（`albumId` = `ALL VIDEOS` / `ALL PHOTOS`） | アプリ内のゴミ箱へ移動する．**Macアプリから元に戻せる** |
| アルバムから外す | `POST /deleteVideos`（`albumId` = 表示中のアルバム） | そのアルバムの所属から外すだけで，メディアはライブラリに残る |
| 完全に削除 | `POST /deleteVideosCompletely` | 登録情報とアプリ管理内のコピーを削除する．リンクフォルダなど管理外の元ファイルには触れない |
| 実ファイルをMacのゴミ箱へ移動 | `POST /moveVideosToSystemTrash` | 管理内・管理外を問わず実ファイルをmacOSのゴミ箱へ移し，成功した項目をライブラリから外す |

通常アルバムを開いているときは「アプリ内のゴミ箱へ」の代わりに「アルバムから外す」を表示します．Macのゴミ箱への移動が一部失敗した場合は，成功した項目だけをライブラリから外し，失敗した項目は理由とともに残します．アルバム削除では中身の扱いとして同じ選択肢を利用できます．

### 視聴位置と「続きを見る」

視聴位置は `localStorage` の `mms_progress`（`{videoID: {t: 秒, at: 最後に見た時刻}}`）に持ちます。
旧形式の `resume_<id>` は読み取りだけ引き継ぎます。エントリは 300 件で古い順に間引きます。

- サムネの下端に**視聴済みバー**を出します（2%〜98% のものだけ。見終わったものには出ません）
- **「続きを見る」タブ**（最後に見た順、残り時間と視聴率つき）。ホームと同じグリッドで、このタブ専用の再生リストになるので
  開いた動画の「次の動画」も続きを見るの並びになります
- 最後まで再生した動画は記録を消して一覧から外します
- 再生画面を閉じたときは一覧を作り直さず、視聴済みバーとハートだけ差し替えます（スクロール位置を保つため）

### アップロード・移動・アルバム作成

これで Web UI は閲覧専用ではなくなりました。

**アップロード**（`POST /upload`）はアルバム詳細から。ボタンでファイルを選ぶか、**画面へドラッグ&ドロップ**します。

- 送信前に**拡張子**（`UploadFilename.sanitize` と同じ 11 種）と**サイズ**を確認して弾きます。上限は
  `GET /server/status` の `maxUploadBytes` から取ります。Swifter はボディを丸ごとメモリに載せてから
  ハンドラを呼ぶので、大きすぎるものを送らせないこと自体が保護になります。
- ファイル名は `X-Filename` にパーセントエンコードして渡します（HTTP ヘッダに日本語をそのまま載せられないため）。
- 進捗を出したいので `fetch` ではなく `XMLHttpRequest` を使っています（`upload.onprogress`）。**1 件ずつ順番に**送り、中止もできます。
- サーバーは取り込みを非同期で始めて即 OK を返すため、完了後に少し待ってから一覧を読み直します。

**移動**（`POST /move`）は複数選択して「移動」から。サーバーの `moveVideos` は移動元が
`ALL VIDEOS` / `ALL PHOTOS` のときだけ所属を外さないので、UI の文言もそれに合わせています。

| 移動元 | 実際の動作 | シートの見出し |
|---|---|---|
| ALL VIDEOS / ALL PHOTOS | 元に残したまま追加 | 「どのアルバムに追加しますか」 |
| 通常のアルバム | 元から外して移動 | 「どこへ移動しますか」 |

**アルバム作成**（`POST /albums/create`）はアルバムタブの「＋ 新規アルバム」から。種類は動画／写真／混在。
サーバーは `ALL VIDEOS` / `ALL PHOTOS` と同名なら黙って何も作らないので、同名・予約名は手前で弾いて理由を出します。

なお `DELETE /albums/:id`（アルバムの削除）はまだ Web UI から使っていません。

### 再生の設定（自動再生・リピート・シャッフル）

以前は `ended` で必ず次へ進んでいました。いまは再生画面の上段で切り替えられます。設定は `mms_playback` に保存され、次回以降も維持されます。

| 設定 | 動き |
|---|---|
| 自動再生 | オフなら再生し終わってもその場で止まる |
| リピート | なし → 1 本（頭に戻して再生）→ 全体（末尾で先頭へ折り返す）の順で切り替え |
| シャッフル | 次を無作為に選ぶ。「前へ」は実際に見てきた順（`playedStack`）を辿る |
| 再生速度 | 0.5〜2 倍。ネイティブのコントロールから変えた場合も拾って覚える |
| 音量 | 音量・ミュートを覚えて次の動画にも引き継ぐ |
| PiP | ピクチャインピクチャ。非対応環境ではボタンを隠す |

**写真はこれらの対象外**です（順送りのみ、漫画モードで左右反転）。再生設定の行も写真では隠します。

### マイライブラリ（履歴・お気に入り）

アルバムタブの先頭に、サーバーを介さずブラウザ側だけで組み立てる仮想アルバムを 3 つ置いています（iOS 版と同じ考え方）。

| 仮想アルバム | 保存先 | 中身 |
|---|---|---|
| 再生履歴 | `mms_history` | 最後に開いた順（最大 200 件）。ショート再生でも記録される |
| お気に入り | `mms_favorites` | 再生画面の「お気に入り」で登録。サムネにハートが出る |
| ショートのお気に入り | `mms_shorts_favorites` | **クリップ開始位置ごと**覚える（`{id, t}`） |

これらは並べ替えず「記録した順」で出します（順番そのものが意味を持つため）。一覧の HTML は使い回すので、
件数バッジだけ `refreshVirtualCounts()` で貼り替えます。

### アルバム詳細

- **並べ替え**にサイズ・更新日・最後に開いた日を追加しました（サーバーは以前からこの 3 つを送っていました）
- **24 件ずつの遅延描画**にしました。以前は全件を一度に DOM 化していたので、数千件のアルバムで固まりました
- **複数選択**（「選択」ボタン）→ お気に入り一括登録 / ゴミ箱へ / 完全に削除。外す先は常に「いま開いているアルバム」なので、
  ALL VIDEOS・ALL PHOTOS ならゴミ箱行き、通常アルバムなら所属を外すだけになります

### キーボード操作

一覧のカードは `<div>` のままですが `role="button"` と `tabindex="0"` を付け、Enter / Space で押せるようにしました。
フォーカス位置は `:focus-visible` でアクセント色の枠を出します。

### 共有リンク

`#watch/<メディアID>` を開くと、そのメディアを直接再生します。動画はホームの並びから、
写真はホームに含まれないので `ALL PHOTOS` から探します。開く前に履歴の起点を `#home` に置き換えるので、
「戻る」でサイトの外に出ずホームへ帰れます。

### 補足

- サムネイルは iOS 版と同じ URL（`/thumbnail/:id?original=true`）を使うので、サーバー側の生成キャッシュを共有します。
- 一覧は 12 件ずつの遅延描画（`IntersectionObserver`）で、大きなライブラリでも初期表示が重くなりません。
- 画質切り替えは `?q=` を差し替えるだけで、`/video/:id/prepare` は呼びません。プロキシはサーバー全体で 1 本しか保持できず、ブラウザから生成すると視聴中の iOS クライアントのプロキシを壊すためです（プロキシが既にあればそれを使います）。

## ソース構成

macOSアプリは，機能単位のMVVM構成です．画面を追加・変更するときは，まず対象の`Features`配下を確認してください．複数機能から共有する実装だけを`Common`へ配置します．

```text
AllServerForMac/
├── App/
│   ├── Models/          # アプリ全体の画面選択など
│   ├── ViewModels/      # Feature間の依存を組み立てるAppViewModel
│   └── Views/           # ルート画面とウインドウ設定
├── Common/
│   ├── DesignSystem/    # 色，余白，共通ViewModifier
│   ├── Utilities/       # 画像処理，排他制御などの汎用処理
│   └── Views/           # 複数Featureで使う共通View
└── Features/
    ├── Dashboard/
    ├── Library/
    ├── MediaAnalysis/
    ├── Navigation/
    ├── Playback/
    ├── Server/
    ├── Settings/
    └── Storage/
```

各Featureは，必要に応じて次のフォルダを持ちます．

| フォルダ | 役割 |
|---|---|
| `Models/` | 永続化データ，値オブジェクト，画面状態の型 |
| `ViewModels/` | 画面状態とユーザー操作を扱う`ObservableObject` |
| `Views/` | SwiftUIによる表示と入力イベントの受け渡し |
| `Services/` | HTTP，ファイルI/O，メディア変換などの副作用 |
| `Components/` | Feature内だけで共有する小さなViewや再生部品 |

主要な依存関係は，`AppViewModel`が`LibraryViewModel`，`ServerViewModel`，`PlaybackCoordinator`，`AppSettings`を生成し，`ContentView`から各Featureへ渡す形です．Viewは表示とイベント通知を担当し，ライブラリ操作，サーバー制御，ストレージ集計などの状態変更はViewModelまたはServiceへ集約します．Feature固有の型を`Common`へ置かず，`Common`から`Features`へは依存させない方針です．

| 主な実装 | 役割 |
|---|---|
| `App/AllServerForMacApp.swift` | アプリのエントリーポイント |
| `App/ViewModels/AppViewModel.swift` | アプリ全体の依存関係と画面選択の管理 |
| `Features/Library/ViewModels/LibraryViewModel.swift` | ライブラリ状態の基点 |

## 差分切り替え再生

同じタイムラインから書き出した「衣装違い」「状態違い」のような **差分動画** を、1 本ずつ順番に見るのではなく、再生しながら見せる絵だけを差し替えて見るための機能です。

### 探し方（アルバム画面 →「差分動画を探す」）

判定は 3 段階です。

1. **尺で束ねる。** 差分は同じタイムラインから書き出すので尺がフレーム単位で揃います。既定の許容差は ±0.20 秒。ここでほとんどの組み合わせが落ちるので、重いフレーム展開はごく一部にしか走りません。
2. **束の中だけでフレームを突き合わせる。** 尺の 8% / 24% / 40% / 56% / 72% / 88% の位置から同じ時刻のフレームを起こし、それぞれ dHash（`PerceptualHash`）にして平均ハミング距離を取ります。先頭と末尾は黒フレームやフェードでどの動画も同じ絵になるため避けています。
3. **ファイル名の近さでしきい値を少し上下させる**（`TitleSimilarity`）。

実測（4K/60fps の同一シリーズ 10 本）での目安:

| 関係 | フレームの平均距離 | ファイル名の近さ |
|---|---|---|
| 衣装・状態だけが違う差分どうし | 2 〜 9 | 0.57 〜 0.94 |
| 同じ動きだがキャラクターが違う | 14 〜 19 | 0.41 〜 0.67 |
| まったく別の動画 | 26 以上 | 0.00 〜 0.42 |

**この 2 つは得意分野が違います。** フレームは「別キャラかどうか」をはっきり分けますが、ファイル名は分けられません（`水着ミカが負ける動画` と `水着ヒフミが負ける動画` は 1 語しか違わないので、衣装違いと同じくらい近く出ます）。逆にファイル名は「無関係かどうか」をきれいに分けます（0.42 以下と 0.57 以上）。

そこで主役はフレームに置き、ファイル名は **しきい値を上下させる補助** としてだけ使います。効き幅は「タイトルの効き」スライダー（既定 ±4、0 でファイル名を完全に無視）で、

```
実効しきい値 = 似ている度合い + 効き × (名前の近さ − 0.5) × 2
```

名前がそっくりなら少し甘く、まるで違えば少し厳しく判定します。名前の近さだけでフレームの隔たりを埋め切れない幅に抑えてあるので、スライダーを最大にしてもミカ系とヒフミ系が混ざることはありません（いちばん危ない組でも実効しきい値 11.1 に対しフレーム距離 14.2）。

ファイル名の指標には**最長共通部分文字列を Dice で正規化したもの**を使っています。文字バイグラム・レーベンシュタイン・前後一致とも実測で比べたうえで、いちばんよく分かれたものです。連続の長さを見るので、`水着`／`全裸` のように差し替えが端にあると芯がまるごと残って高くなり、`ミカ`／`ヒフミ` のように真ん中で変わると芯が割れて低くなります。

なお、フレームを起こせなかった動画は名前がどれだけ近くても対象にしません（名前だけでは根拠として弱く、別キャラを引き込むため）。各グループの見出しには実測の「絵の差」と「名前の近さ」が出るので、スライダーを動かす手がかりにできます。

### 指紋は残しておく（`VariantSignatureStore`）

4K の動画1本から指紋を作るのに数秒かかります（時刻ぴったりのフレームを6枚起こすため、毎回キーフレームから復号し直すことになる）。探すたびに作り直していると、一度再生して戻ってきただけで数十秒待たされます。

指紋はファイルの中身だけで決まるので、`~/Movies/MacVideoServerData/VariantSignatures.json` に残して使い回します。実測（4K/60fps を 10 本）で **初回 40.3 秒 → 2 回目以降 0.00 秒**。アプリを再起動しても効きます。

- 中身が変わったかどうかは実ファイルの**サイズと更新日時**で見ます（`fileHash` は全バイト読むのでこの用途には高すぎる）。更新日時はファイルシステムで丸め方が違うので 1 秒までは同じ扱い。印が合わないものはその場で捨てて作り直します。
- フレームの取り出し位置を変えたら前の指紋は比べられない（同じ時刻同士でないと意味がない）ので、サンプル位置そのものを印にして丸ごと捨てます。
- あくまで作り直せる副産物なので、読めなければ黙って空から始め、書けなければ黙って諦めます。上限は 20,000 件で、超えたら使った順に古いものから捨てます（1 件あたり数百バイト）。

**この一覧からの再生も、ほかの再生モードと同じくウィンドウ全体で表示します。** ただし探索画面は破棄せず、その上へプレイヤーを重ねます。プレイヤーを閉じると、再生前と同じ探索画面がそのまま現れます。

- `ScrollView` 自体を再生中も残すため、スクロール位置、選択した組み合わせ、表示中のグループが変わりません。
- 再生中はフレームの照合を止めます（再生の邪魔になるため）。途中まで作った指紋は残るので、閉じたときに続きから進みます。
- プレイヤーの中で差分を削除した場合は、閉じた時点で顔ぶれを見直します（変わっていなければ何もしません）。

探索結果そのもの（見つけたグループと、どれを選んだか）は `AppViewModel.variantFinder` が持ちます。再生後やアルバムを開き直したあとも、同じ顔ぶれなら照合をやり直しません。

一覧を選択から直接始めた差分切り替え再生（ツールバーの「差分切り替え再生」や `Y`）は従来どおりウィンドウ全体を占有します。同じ顔ぶれを渡されたときは照合自体を行いません（途中で中止した場合は覚えないので、次に開いたときは続きから進みます）。取り込み直したファイルを拾わせたいときはヘッダの「探し直す」を使います。

照合が途中でも、見つかったグループから先に選んで再生できます。

一覧は `ContentView` の最上位オーバーレイとして、ウィンドウをほぼ埋める大きさで開きます。プレイヤーも同じ `ZStack` に置き、探索画面より上の表示順にすることで、探索画面を破棄せず全画面再生できます。

グループの札は**横に並べます**。縦一列に積むと、1グループはたいてい数本しかないので、ウィンドウを広げても右側が余るだけでした。札1枚にタイルが2〜3個入る幅を下限にした適応段組みで、幅 2476pt なら 5 列（札 484pt・札の中はタイル2列）、1796pt なら 4 列、932pt なら 2 列と、余りを出さずに詰まります。サムネイルの大きさはフッタのスライダーで 110〜320px（札の幅もこれに連動、設定は次回に残ります）。

### 再生

束からチェックした 2 〜 9 本を、`SynchronizedPlayerGroup` で **同じホストクロックに合わせて一斉に** 走らせます。切り替えは重ねたレイヤーのうちどれを不透明にするかを変えるだけなので、継ぎ目もシークも入りません。聞こえるのは表示中の 1 本だけで、裏の動画はミュートしたまま走り続けます（止めると切り替えた瞬間に頭出しからやり直しになるため）。

- **自動切り替え**：下限〜上限（既定 3.0 〜 6.0 秒）の範囲からランダムに選んだ秒数ごとに切り替え。上下を同じ値にすれば固定間隔になります。「同じものを続けない」を入れておくと、切り替えたのに絵が変わらない瞬間が混ざりません。設定は次回起動まで残ります。
- 映像は比較結果を濁さないよう従来どおり即時に切り替えます．現在の差分番号とタイトルは左上へ常時表示し，操作パネル内の選択表示は大きな色反転ではなく細い下線で穏やかに示します．
- **手動切り替え**：キーボード上段 **Q W E R T Y U I O** が左から順に 1 本目〜9 本目に対応（数字キーは他のプレイヤーと同じく 0%〜90% の割合ジャンプに使うため、そちらへは割り当てていません）。`N` / `B` で次・前、`V` でランダム。手で切り替えたときも次の自動切り替えまでの時間は測り直します。操作パネルの各チップには、その差分に割り当たっているキーが出ます。
- **その他のキー**：`A` 自動切り替えの入/切、`−` / `+` 間隔を増減（0.5 秒より上は 0.5 秒刻み，0.5 秒以下へ短くするときは 0.1 秒刻み）、`P` 操作パネルを出しっぱなしに固定、`?` ショートカット一覧、`Esc` 終了。再生・シーク・閉じるは通常の動画プレイヤーと同じキーです（設定 →「ショートカットキー」で変更可）。設定で変えたキーのほうが上段キーの固定割り当てより優先されます。
- 選択済みの動画が 2 本以上あれば、アルバム画面のツールバーの「差分切り替え再生」や `Y` キーから直接始められます（探す手順を挟まなくてよい）。
- **操作系は普段隠れています**（[全プレイヤー共通](#操作系の自動的な出し入れ)）。差分のチップと間隔の設定も一緒に出入りし、`P` で出しっぱなしに固定できます。ただし **差分の切り替え，シーク，再生・一時停止のショートカットでは操作系を出しません**。見ている最中に何度も押すキーなので、そのたびにパネルが映像へ被ると邪魔になるためです。

### iPhone / ブラウザから使う

検出は必ず Mac 側で行います。実ファイルを持っているのは Mac だけで、フレームを時刻ぴったりで何枚も起こす処理をクライアントへ持っていく術がないためです。クライアントへ渡すのは「どの動画が同じ束か」という結果だけです。

`GET /albums/:id/variants` が探索結果を返します。指紋づくりに時間がかかるぶん、`/video/:id/prepare` と同じく **その場では今わかっていることだけを返し、残りは裏で作ります**。クライアントは `state` が `ready` になるまで少し間を空けて尋ね直します（`groups` は途中でも入っているので、見つかったものから先に選べます）。

```
GET /albums/:id/variants?tolerance=0.2&distance=10&title=4
→ { "state": "scanning" | "ready", "scanned": 3, "total": 10, "groups": [ … ] }
```

指紋の置き場は Mac の画面側と共通なので、**どちらかで一度調べれば、もう一方は待たされません**（実測: 初回 41.4 秒 → 2 回目 0.4 秒）。サーバーを再起動しても効きます。

iOS 版（[VideoPlayer](../VideoPlayer)）の同時再生は **4 本まで**です。無線越しに本数ぶんの映像を同時に受け取って展開するので、Mac の 9 本は現実的ではありません。

### 見比べて消す（削除モード）

差分として並べて初めて「これは中身がまったく同じだ」と分かることがあります。そのために、再生したまま要らないものを選んで消せます。

- `D`（またはシークバー横のゴミ箱ボタン）で **削除モード**。チップの左にチェックが出ます。
- 表示中の差分を印付け／解除するのは `X`。削除モードに入っていなければ、そのまま入ります。見比べて「同じだ」と気づいた瞬間に印を付けられます。
- 削除モード中でもチップ本体を押せば従来どおり切り替わります（見比べないと判断できないので、印付けと切り替えは別の当たり判定にしてあります）。
- 「削除」を押すと、他の画面と同じく **ゴミ箱に入れる / 完全に削除** を選ぶ確認が出ます（選んだファイル名の一覧つき）。
- 消したぶんは再生から外れ、**残りは見ていた位置のまま同期再生を続けます**（実測で位置の引き継ぎ・ずれ 0.0000 秒・消したプレイヤーの停止を確認）。見比べる相手が 1 本以下になったらプレイヤーを閉じて一覧へ戻ります。
- 削除モードの間は操作系を出したままにします（選んだ結果が見えないと判断できないため）。

### 注意

本数ぶんの動画を同時にデコードし続けるため、**4K の差分を何本も選ぶと重くなります**（上限は同時再生と同じ 9 本）。ずれは 4 秒ごとに点検し、0.25 秒を超えたときだけ揃え直します（揃え直しは preroll のぶん一瞬引っかかるため、見て分かる大きさになるまでは放置するほうが滑らかです）。

### 一時停止と再開について（`SynchronizedPlayerGroup`）

`AVPlayer.pause()` は1本ずつ止まるので、止まった位置が数十ミリ秒ばらつきます。再開時に `setRate(_:time:atHostTime:)` へ `.invalid`（＝各自がいま指している位置）を渡すと、そのばらつきが固定されたうえ一時停止のたびに積み上がります。4K60 を 6 本並べた実測では、一時停止と再生を 5 往復しただけで 0.34 秒ずれました。

そこで再開時は、いちばん遅れている位置を明示して開始位置ごと揃えます（進んでいるほうへ合わせると、遅れている側が前へ飛んで数フレーム抜けるため）。12 往復してもずれは 0.0000 秒に収まります。

ただし **開きが 1 秒を超えていたら位置には触りません**。同時再生は動画ごとに尺が違い、短いものが終われば位置が何十秒も開きますが、それは直すべきずれではなく、そこへ巻き戻すと長いほうが逆再生したように見えてしまいます。すでに最後まで行ったプレイヤーも基準から外します。シークを指示されたときも触りません（行き先を決めたのは呼び出し側で、割合シークは動画ごとに別々の位置へ飛ばすのが正しい）。

一斉スタートの猶予（`syncStartLeadSeconds`）は、そのまま「再生を押してから絵が動き出すまで」の待ち時間になります。配り終えるのに要するのは 2ms 程度で、0.08 秒以下にすると待ち時間は 90ms 前後で頭打ちになったため、0.08 秒にしています（0.15 秒だと 153ms かかっていました）。

## 操作系の自動的な出し入れ

シークバーや各種ボタンは、一般的な動画プレイヤーと同じで **カーソルを動かしている間だけ** 出し、**2.5 秒動かさなければ引っ込めます**（そのときポインタも消えます）。次にマウスを動かすか、拾われるキーを押せば戻ります（差分切り替え再生で差分を切り替えるキーだけは例外で、出しません）。

引っ込めてはいけない事情があるときは出したままにします。

| 事情 | 理由 |
|---|---|
| つまみの上にポインタが乗っている | 触っている最中に消えると操作できない |
| 一時停止している | 消えていると再生ボタンの在り処が分からなくなる |
| ショートカット一覧・音声ミキサー・チャプター一覧を出している | 一緒に消えると操作の脈絡が切れる |
| `P` で固定した | じっくり触りたいときの明示指定 |

この出し入れは `Features/Playback/Components/PlayerChromeController.swift` に集約してあり、**同時再生・分割再生・差分切り替え再生・スライドショー**が共有します。通常再生（`VideoPlayerView`）だけは、同じ表示条件で関連動画パネルやサムネイル帯まで出し分けていて素直にこの形へ収まらないため、先に入っていた自前の実装をそのまま残しています（振る舞いと 2.5 秒という間隔は揃えてあります）。スライドショーのシークバーは AVKit 標準のもので、それ自体が同じように隠れるため触っていません。

操作系は映像に **重ねて** います（以前は映像の下に積んでいたため、出入りのたびに映像が伸び縮みしていました）。

## セキュリティ / 注意点

- **ローカル LAN 専用**を想定しています（通信は平文 HTTP）。インターネットへ直接公開しないでください。
- PIN はアプリ画面に表示され、再生成も可能です。クライアント側はキーチェーン/設定に PIN を保持します。
- スケジュール起動で `pmset repeat cancel` を使うと、**他に設定済みの繰り返し起床スケジュールも消えます**（個人利用なら通常問題ありません）。
- スリープ起床は電源接続が前提です（ノートのバッテリー駆動では起床しません）。

### 2026-07-06 データ保護・堅牢化アップデート

公開品質を目指した集中的な監査で、データ消失につながる問題と「想定しにくいバグ」を修正。

**データ保護（クレームレベルの修正）**

- `library.json` 破損時に空のライブラリで上書きしてしまう問題を修正。壊れたファイルは `library.corrupted-<日時>.json` に必ず退避し、**3世代ローテーションのバックアップ**（`library.backup.json` / `.2` / `.3`）から自動復元する。空に近いデータや新しいスキーマのデータではバックアップを更新しない（汚染防止）
- ライブラリが空の状態で孤児ファイル整理（`cleanUpOrphanedFiles`）が走ると `Videos/` 内の実ファイルを全削除しうるカスケードをガードで遮断
- リモート（iOS/Web）から「すべての動画/画像から外す」を実行すると実ファイルまで完全削除されていた経路を**ゴミ箱行き**に変更。完全削除は明示的な「完全に削除」操作のみ
- ライブラリから削除したとき、**アプリ管理外の元ファイル（フォルダインポートの参照元）には一切触れない**よう変更（以前は Finder のゴミ箱へ移動していた）
- アプリ内の削除操作全般で「ゴミ箱に入れる / 完全に削除」を必ず確認ダイアログで選択させるよう統一
- **二重起動検出**（`flock`）: Xcode 実行と通常起動などが同じライブラリを同時に開いた場合、後から起動した側は保存を一切行わず警告して終了（後勝ち上書きによるサイレント消失防止）
- 保存書き込みを専用直列キュー＋世代番号で直列化し、デバウンス保存とフラッシュ保存の追い越しレース（古い内容が後から勝つ）を排除。完全削除の直後はデバウンスを待たず即時書き込み

**想定しにくいバグの修正**

- パス判定の `hasPrefix` 境界バグ（`VideoServerForMac_Media_backup` のような兄弟フォルダをアプリ管理と誤判定）を修正
- リンク切れシンボリックリンクが毎起動修復に失敗し続ける問題（`fileExists` がリンクを辿る仕様との非対称）を修正
- 変更系 API（アルバム作成/削除/移動/完全削除）が反映前に成功応答を返し、直後の取得に古い状態が返る問題を修正（反映完了を待って応答）
- HTTP ルートが videos / albums を別々のロックで読むことによる不整合応答を、単一スナップショットの原子的読み取りに統合
- サムネイル/プロキシのファイル名をパース済み UUID の正規形で統一（大文字小文字を区別するボリューム対策）
- `fileHash` に計算時点のファイル更新日時を持たせ、中身が変わったファイルの古いハッシュを使い続けない（重複チェックの誤判定防止）
- `getIPAddress` が Parallels/Docker 等の仮想ブリッジを拾う問題を修正（en 番号の小さい順を優先、リンクローカル除外）
- ゴミ箱の `trashedDate` が時計変更で未来になった場合に現在時刻へ丸めて自己修復
- アクセスログに PIN がクエリごと平文で残る問題を修正（`pin=****` にマスク）
- Bonjour 公開失敗・名前衝突リネームをステータス表示で可視化（`didNotPublish` 実装）
- `library.json` に `schemaVersion` を導入。新しい形式のデータを旧ビルドの書き戻しから守る
- 大量インポート中の進捗表示が1件ごとに全体再描画を起こしていた問題を修正（25件ごとに間引き）
- `/server/status` が `maxUploadBytes` を公開し、クライアントが送信前にサイズ超過を弾けるように（Swifter はボディを全てメモリ展開するため、サーバー側チェックだけではメモリ枯渇を防げない）

**新機能**

- **詳細設定シート**（サイドバーの歯車アイコン）: インポート時コピー/参照の切替、ゴミ箱自動削除期限（なし/30日/90日）、リンク切れ自動整理、認証オフ時も削除系 API に PIN 要求、サーバー表示名、アップロード上限、自動重複チェック間隔、インポート並列数、サムネイルキャッシュ上限、エクスポート形式
- **エクスポート機能**: 選択メディア/アルバム/フォルダ丸ごとを、アルバム階層とファイル名を再現して任意フォルダへコピー書き出し（元ファイル紛失に備える安全弁）
- サイドバー: アルバムの複数選択→新規フォルダにまとめる、フォルダへのドラッグ＆ドロップ移動、フォルダタイトルクリックで開閉、選択中アルバムの自動展開
